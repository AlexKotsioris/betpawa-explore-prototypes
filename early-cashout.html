Single bet card — handover My Bets · single bet card · {{ specVariantLabel }}
WHAT CHANGED The single bet card renders the one selection directly, in the same visual order the Betslip uses — no grey ODDS/STAKE/PAYOUT summary box, no accordion. Since the last handover: win bonus is gone from My Bets entirely (payout is stake × odds, nothing else); the kick-off time now shows in every state, settled included; the market type carries an info button whose explainer copy is fetched per market type from the CMS; bet IDs render in full (no ellipsis); and lost bets gain a Request support flow. The primary action is a lime Re-bet button above the secondary row. You opened this from a long-fixture card, so every measurement below describes the two-line variant exactly as rendered here: team per row, that team's goals beside it. Build it this way for any fixture whose full "home - away" string runs over 32 characters; shorter fixtures stay on one line with a combined score.
STRUCTURE, TOP TO BOTTOM
1 · ID row "ID:" label and bet ID both bold slate, 14px, never truncated — the row wraps before the ID ellipsises. The ID is a tap target that opens bet detail; a 20×24 copy-ID button sits 4px after it and fires the "Bet ID copied" toast. Right side of the row: the live clock (orange, 13px bold) while in play, or the status pill once settled. The row is flex-wrap, so on narrow slips a long status pill ("Cashed Out") drops to a second line instead of squeezing the ID.
2 · Event line Build this as two rows inside a 1px-gap column, one team per row — that is what this card is doing and it is the layout to implement for fixtures this long. Row one is the home team, row two the away team, both 14px regular, each free to wrap internally rather than truncate. Each row ends with that team's own goal count, 14px bold orange, right-aligned in a fixed 16px column so the digits stack vertically. Do not concatenate the names back into one string and do not print a combined score anywhere on this card. Whole fixture on one 14px regular line. The right of this line is state-dependent: pre-match shows the kick-off time in grey regular, live shows the combined score in orange bold. Same slot, one or the other, never both. Placement time is not on this line — it sits on the meta row above.
3 · Market type Own line, 13px slate. Derived by splitting the market string on " - " and taking the first part, e.g. "1X2 | Full Time". An 18×18 info button follows it: tapping toggles a dark explainer bubble under the row. That copy is not hardcoded — look the market type up in the CMS market-info collection and fall back to a generic "market rules for this bet type" line when the key is missing.
4 · Selection + odds One flex row, baseline aligned, space-between. Left: the selection as the actual team name in bold — resolve the outcome token against the fixture, so "1" renders the home team, "2" the away team, "X" renders "Draw". Never print "Home", "Away" or the raw token. Right: the word "Odds" in grey regular followed by the value in bold, 2 decimals.
5 · Hairline divider 1px var(--bd), 6px padding above the totals row. Separates the selection from the money.
6 · Stake and Payout Both on one row, labels in grey regular, values in bold. Stake carries no currency code; Payout does ("GH₵ 1,240.00"). Payout is stake × odds — there is no win-bonus row on this card and no bonus in the maths. Payout value takes the result colour — green when won, red when lost, slate while open — and is hidden entirely on void bets.
7 · Action row Settled cards only. Primary is a full-width lime Re-bet button (40px, rotate icon, regular label, count badge — "1" for a single) that reloads the selection into the betslip and slides it up. Under it, a wrapping secondary row: Share slip as a white outline button, and on lost bets a full-width "Request support for this bet" button with a phone icon. Mixed case, never uppercase.
8 · Request support overlay Tapping the support button opens a centred modal: title "Request support", a line naming the bet ID, an editable phone field prefilled from the account, then Cancel and lime Confirm. Confirm closes the modal and fires the call-back toast; it must not navigate away or collapse the card.
STATES The card has one layout and three states. Only two slots change between them — the right of the ID row and the right of the event line. Everything else (market type, selection, odds, stake, payout) is identical in all three.
Pre-match ID row right: empty — no pill, no clock. Kick-off time sits on the market-type row, 14px regular in secondary grey (var(--tx2)), e.g. "3:00 pm, Sat 18/07". This is the start time of the match, not the time the bet was placed — those are different values and must not be swapped (placement time appears on the bet detail page only). No score exists yet, so nothing orange appears anywhere on the card.
Live The kick-off time is replaced, not supplemented. ID row right: the match clock in orange 13px bold ("2H | 67'"). The score does not live in one slot here — it is split across the two team rows, one goal count per team, each right-aligned to the same 16px column. The reader maps score to team by row, so a combined score would be wrong. Clock and both goal counts all use --c-text-warning (#FF7A00) — one orange for live across the whole card, never a second shade. The kick-off time is replaced, not supplemented. ID row right: the match clock in orange 13px bold ("2H | 63'"). Event line right: the combined score in orange 14px bold ("1 - 0"). Both use --c-text-warning (#FF7A00) — one orange for live across the whole card, never a second shade.
Settled ID row right: the status pill (WON / LOST / VOID / CASHED OUT) takes the clock's slot. The kick-off time stays visible in grey — settled cards must still say when the match was played, matching the pending layout. The Payout value picks up the result colour, the trophy icon appears on large wins, and the action row (Re-bet, Share slip, support on losses) appears beneath.
TOKENS Card: #FFFFFF surface, 1px var(--bd) border, radius 12, 12px padding, 8px gap between rows. Text slate #252A2D, secondary var(--tx2), live orange #FF7A00, won green #76AC08, lost red #CC371B. Roboto 400/700 only, 13/14px in the card body.
WATCH OUT FOR The team-name resolution needs both the market token and the fixture's home/away names to be present on the leg payload — if the fixture string is missing the selection silently falls back to the raw token. Stake must stay currency-free while Payout keeps the code; that asymmetry is deliberate. Do not reintroduce a win-bonus row or bonus maths on this card. Never ellipsise the bet ID to make a pill fit — wrap the row instead. Market explainer copy is CMS content, not a string constant.
Multibet card — handover My Bets · multibet card · summary-box variant
WHAT CHANGED The multibet card is a filterable summary. Leg counts by state sit under the ID as tappable chips — the first reads "N legs" — and tapping one expands the matching legs inline, directly above the odds box. The chips are the only expand affordance. Since the last handover: the win-bonus row is gone from the summary box and from the payout maths (payout is stake × odds); each expanded leg carries its time on the team lines rather than a separate clock line — kick-off time beside the home team, date beside the away team; lost picks are marked by the status dot alone, with no strikethrough and no red text; cashed-out slips suppress the Pending, Live and Won chips; and combo bets render as a compact summary instead of a per-leg list. Typography stays flat — only Payout, scores, the selected team and chip labels are bold.
REMOVED SINCE LAST BUILD
Bet details toggle The centered Bet details / Hide details button with the rotating chevron is deleted. Expansion is driven entirely by the state chips — tap a chip to open, tap the active chip to close.
Leg-count badge The bordered pill showing 3 beside the bet ID is gone. Leg count reads from the state chips and from the Re-bet button badge.
Bare result-count chips Count-only chips (dot plus number) are replaced by labelled state chips — 3 Pending, 2 Live, 4 Won, 1 Void. Never render the count without its label. The leading chip reads "3 legs", not "3 All".
Win bonus row Removed from the summary box, the bet detail page and the payout calculation. Payout is stake × odds everywhere; an open multibet and the same slip once settled must show the same figure.
Struck-through lost picks Lost selections keep slate text with no line-through. The result dot in front of Odds is the only result signal — do not tint the pick red.
Standalone leg clock line The right-aligned time line above each leg's teams is gone. Time sits on the team rows instead: kick-off time on the home row, date on the away row — the same shape as a single bet card.
Left-edge leg dot The dot no longer sits at the left edge of the leg row. It belongs immediately in front of the word Odds.
Currency on Stake and Win bonus Those two values are bare numbers. Only Payout and the cashout amount are prefixed with GH₵.
Bold button labels Re-bet, Request Cashout and Accept are no longer bold. Bold is reserved for values and status labels, not actions.
Clickable team names Team names in a leg are plain text. They do not navigate to an event page.
STRUCTURE, TOP TO BOTTOM
1 · ID row ID: in grey, bet ID in regular slate at 14px — the same size as a team name, and a tap target that opens the full bet detail; it must stop propagation. Two 24×24 grey icon buttons follow: copy-ID (clipboard, fires the Bet ID copied toast) and share (opens the share sheet). Right of the row: live activity icon while in play, status pill once settled.
2 · State chips A 22px-tall pill row, 11px bold labels, 7px padding. First chip is the total, labelled "legs", then one pill per non-empty state in fixed order: Pending (grey dot), Live (orange dot, orange text), Won (lime dot, green text), Lost (red dot, red text), Void (a small × glyph instead of a dot, grey). Each reads count then label. Counts derive from each leg result, with pending legs split into Live and Pending by whether the leg time is clock-shaped (2H | 63′, HT). On a cashed-out slip only the legs and Void chips render — Pending, Live and Won are suppressed, because the bet was settled early. Chips are buttons: tapping one filters and expands the leg list; the active chip gets a var(--s2) fill and a border in its own colour; tapping it again collapses. Right of the row: the placement timestamp, grey 13px.
3 · Expanded legs Renders directly under the chips and above the odds box — never below it. Only legs matching the active filter are shown, separated by a hairline. Each leg: home and away stacked, the home row carrying the kick-off time (or live clock, orange bold) and the away row the date, each row ending with that team's score bold and right-aligned in a fixed 16px column; then the market type; then the selected team in bold with the status dot and Odds value on the right. Team names stay slate with no strikethrough in any result state — only scores and the live clock are orange.
3b · Combo bets A combo (several markets on one fixture) never expands into a leg list. It renders the fixture once — home and away stacked, each with its own score column, orange while live — then the markets as a bulleted list, each bullet taking the result dot colour, with a "Combo bet" pill on the last row. No per-leg times, no duplicate event rows.
4 · Cashout Leg (per leg) Open legs carry a Cashout Leg button with a timer icon and an info button beside it. Requesting shows a shimmer, then the frozen state: the original odds struck through in grey with the frozen odds bold in green beside it. The info button opens an explainer sheet. Settled legs never show the control.
5 · Summary box var(--s2) fill, radius 8, 12px padding, 4px row gap. Sentence-case label and value rows, space-between, 14px: Odds, Stake, Payout — three rows only, no win bonus. Labels and values are regular except Payout, which is bold on both sides and carries GH₵. The whole box is clickable and opens bet detail.
6 · Live statistics fold-out (bet detail) On the bet detail page every live leg gets its own "View live statistics" button (38px, outline, orange activity icon, rotating chevron). Open state reveals the pitch graphic with that leg's fixture name and clock, then the stat bars. Each leg toggles independently, keyed by bet ID plus leg index. A live combo shows one fold-out for its single underlying match. Non-live and settled legs show no control.
7 · Action row Open bets: Re-bet and Request Cashout side by side, 44px, 8px gap. Settled bets: Re-bet becomes the primary full-width lime button on its own row, with Share slip demoted to a white outline button beneath and, on losses, a full-width "Request support for this bet" button. Re-bet carries the lime rotate icon, a regular-weight label and a count badge: the number of legs still re-bettable (pending plus void), or the total when none are. WATCH OUT FOR Every nested tap target — bet ID, copy, share, each state chip, the summary box, the freeze controls, the live-stats fold-outs, and all action buttons — must stop propagation, or a tap fires two handlers and appears to do nothing. Live detection is derived from the leg time string, not a boolean flag, so keep the clock format consistent (the chips and the fold-out gate must use the same test, or the counts and the controls disagree). Requesting a cashout must never reorder the bet list. There is no win bonus — payout is stake × odds. And when odds are frozen, the frozen value is what settles, not the struck-through original.
What is Cashout Leg? Cashout Leg lets you lock in this leg early. Once it's locked in, that leg is set in stone with the updated Potential Payout — it can no longer let your multi down, regardless of what happens next. You're not paid straight away. Your multi stays active, with the updated potential win, and you'll be paid if your remaining legs win, or if you Cashout the bet. When a leg is suspended you can't cash it out until it becomes active again.
